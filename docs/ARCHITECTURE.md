# 設計資料

## 全体構成

- 画面は Next.js の Server Components で描画し、更新は Server Actions に集約する
- DB へのアクセスはすべてサーバー側。トランザクションごとに `role = authenticated` と JWT 情報（`request.jwt.claims`）を設定してから SQL を実行するため、RLS が必ず効く（`src/lib/db/rls.ts`）
- ブラウザは Supabase Realtime で配送案件・通知の変更を購読し、届いたら画面を再取得する。切断・再接続・画面復帰時も再取得するので、表示は常に DB の内容が正
- 秘密情報（`DATABASE_URL` など）はサーバー専用の環境変数。ブラウザに渡すのは Supabase の公開キーのみ

## データベース

会社（`companies`）をテナントとして、すべての表に `company_id` を持たせる。主キーは UUID、金額は `numeric(12,0)`（円）、日時は `timestamptz`、業務日付は日本時間。

主な表：`companies` `profiles` `offices` `drivers` `vehicles` `vehicle_assignments` `clients` `delivery_orders` `delivery_status_logs` `delivery_notes` `expenses` `notifications` `audit_logs`

### DB 側で守るルール（`20261027000002_business_rules.sql`）

- ステータス遷移：未割当 → 配車済 → 集荷完了 → 配送中 → 配送完了。例外は 配送失敗（集荷完了・配送中から）とキャンセル（集荷前まで）。配送失敗 → 配車済（再配達）、配車済 → 未割当（配車解除）。それ以外はトリガーで拒否
- ステータスが変わるたびに履歴を自動保存（変更者・メモ付き）。配送完了時に完了日時を記録
- ドライバーの付け外しでステータスを自動で揃える（付けたら配車済、外したら未割当）
- 保存禁止：休職中・退職済みのドライバー、整備中・廃車の車両への割り当て、完了済み案件の担当変更
- 予定の重複は「警告」（保存は可能）。画面側で確認ダイアログを出す

### マスタのルール（`20261027000009_master_rules.sql`）

- 管理コード（D-001 / V-001 / C-001）は未指定なら会社内の最大番号 + 1 を自動で振る（同時登録に備えてロック）
- 対応中（配車済・集荷完了・配送中）の案件があるドライバーは休職・退職にできない。対応中の案件で使っている車両は整備中・廃車にできない
- 退職・廃車にすると現在の担当車両の割り当てを今日で終える。退職者・廃車は新しく担当にできない
- 経費・担当車両に紐づけるドライバー・車両は同じ会社のものだけ
- 画面（選択肢を無効化）→ サーバー処理（理由付きのエラー）→ DB トリガー の3か所で同じルールを守る

### 権限（`20261027000003_rls.sql`）

| | 管理者 | ドライバー |
| --- | --- | --- |
| 自社の案件 | すべて閲覧・登録・更新・削除 | 自分の担当分のみ閲覧 |
| 案件の更新 | 直接更新可 | `driver_update_status()` 経由で 集荷完了・配送開始・配送完了・配送失敗 のみ |
| 経費・分析 | 閲覧・登録 | 不可（集計関数も管理者以外はエラー） |
| 他社のデータ | 不可 | 不可 |

### 集計（`20261027000004_analytics.sql`）

すべての画面が同じ SQL 関数を使うため、画面ごとに数字が食い違わない。

- 売上 = 配送完了案件の配送料金（計上日 = 配送予定日）
- 配送原価 = 経費の合計
- 粗利益 = 売上 − 配送原価、粗利益率 = 粗利益 ÷ 売上 × 100（売上 0 円なら表示しない）
- 遅延 = 予定から15分を過ぎて完了、または予定を過ぎても未完了
- 前月比 = 今月1日〜今日 と 前月1日〜前月の同じ日 の比較

## 画面ごとの実装メモ（Phase 2）

### 配送案件（`/orders`）
- 検索条件はすべて URL に保持（再読み込み・共有で同じ結果）。サーバー側で Zod 検証し、不正な値は無視する
- 1ページ20件をサーバー側で取得（`LIMIT/OFFSET` と件数を別クエリ）。3,000件以上でも全件をブラウザに送らない
- 登録・編集フォームは画面とサーバーで同じ Zod スキーマ（`src/lib/validation/order.ts`）
- 削除できるのは集荷前とキャンセル済みのみ。集荷後はドライバー変更不可、完了・キャンセル後は担当と予定日時を変更不可（画面でも入力を止め、DB でも拒否）

### 配車ボード（`/dispatch`）
- 1日分の案件（キャンセル以外）を取得し、時間 × ドライバーで表示。重なる予定は段を分けて並べる（`src/lib/domain/board.ts`）
- ドラッグ（@dnd-kit/core）で担当変更。横方向の移動は15分単位で時刻変更、未割当の行へ戻すと配車解除
- **警告と保存禁止を分ける**
  - 警告：同じドライバーの時間が重なる → 確認ダイアログで「重複を承知で配車」を選べば保存（監査ログに記録）
  - 保存禁止：休職中・退職済みのドライバー、整備中の車両、集荷後の案件 → DB トリガーとサーバー側で拒否
- 画面に表示していた状態（ステータス・担当）を一緒に送り、DB と違えば保存しない（他の管理者・ドライバーとの同時操作対策）
- キーボード・スマホでは案件をクリック（タップ）して開くパネルから担当と時刻を変更できる

### ドライバー画面（`/driver`）
- データ取得はドライバー権限の RLS の中で行うため、他のドライバーの案件は URL を直接開いても表示されない
- ステータス更新は DB 関数 `driver_update_status()` のみ。取り消せない「配送完了」は確認を挟み、「配送失敗」は理由が必須
- 地図アプリへの案内は Google マップの公開 URL 形式（API キー不要）

### 通知
- 割り当て・割り当て解除・時刻変更・再配達はドライバーへ、ドライバーの完了・失敗は管理者へ、DB トリガーで作成（`20261027000007_dispatch_notifications.sql`）
- 画面は通知・案件の変更を Realtime で受けて再取得する。担当を外れたドライバーにも「解除」の通知が届くので、その画面から案件が消える

## 画面ごとの実装メモ（Phase 3）

### ドライバー・車両・荷主（`/drivers` `/vehicles` `/clients`）
- 一覧の検索条件は URL に保持（`ListFilters`）。今月の実績は `analytics_by_driver` / `analytics_by_client` をそのまま結合するため、売上分析と必ず同じ数字になる
- 詳細の月別グラフは `analytics_order_series(期間, 'month', 荷主, ドライバー)`（`20261027000008_analytics_filters.sql`）。最後の棒（今月）は一覧の数字と一致する（DB テストで確認）
- 担当車両の変更（`assignVehicle`）：車両側・ドライバー側の今の担当を今日で終えてから新しい担当を作る。履歴は `vehicle_assignments` に残る
- 削除は実績がないときだけ。実績があるドライバーは「退職」、車両は「廃車」にする（売上・経費の履歴を残すため）
- 車検・保険は満了まで30日以内で注意、過ぎたら警告（`DEADLINE_WARNING_DAYS`、ダッシュボードと共通）

### 売上・分析（`/analytics` `/analytics/expenses`）
- 期間：今月・先月・直近3か月・直近6か月・指定期間。サーバーで検証し、未来日は今日まで・最長2年。集計単位は45日以内なら日別、120日以内なら週別、それ以上は月別
- 比較：今月 → 前月の同じ日まで、先月 → 前々月、直近3・6か月 → その前の3・6か月、指定期間 → 直前の同じ日数
- 前の期間が0のときは増減率を出さない（0除算しない）。率の指標（粗利益率・遅延率）は「pt」の差で表示
- グラフの色は検証済みの順番（売上 ブルー / 経費 オレンジ / 粗利益 アクア）。1つの軸だけを使い、凡例と「表で見る」を付ける
- 経費は未来日・3年より前を登録できない。登録・編集・削除は監査ログに記録し、分析とダッシュボードにすぐ反映する

## デモ環境

- 体験ボタン → Supabase の匿名ログイン → 訪問者専用の会社を生成（`src/lib/demo/sandbox.ts`）
- データは「今」を基準に生成する。過去6か月の実績、本日の進行中の配送、今後1週間の予定
- 24時間後に自動削除。デモ会社に限り管理者⇔ドライバーを切り替え可能（`demo_switch_role()`）

## デモデータ

架空の「株式会社ミナトエクスプレス」（東京・神奈川で企業間配送）。ドライバー15名（正社員10・業務委託5）、車両18台、荷主12社、直近3か月で約3,000件。

平日と休日の差、月末の増加、7月・12月の繁忙期、お盆の減少、荷主ごとの単価と依頼量の偏り、ドライバーごとの件数・遅延率の違い、件数に比例する燃料費・高速代・外注費を再現している。整合性は `npm run db:verify` と DB テストで確認する。
